COMPARISON OF DESIGN ACCURACY ACROSS METHODS AND SOFTWARE WITH A SPLIT RING BENCHMARK STRUCTURE

DESIGNS

AutoMod: Default settings, random seed 0. Program internal state file provided for reproducibility.
DNAxiS: See SI for settings. Generated closed ring was split manually by removing covalent backbone connections along a cutting plane.
ENSnano: Default settings. Crossover placement was done manually via the GUI by connecting spatially well-alined positions.
MagicDNA: Default settings, extrude method, no spacer nucleotides in between bundles, zigzag uncut staples, only double crossovers. Node points provided.
Manual: See SI for modification placement.

The same scaffold routing was used for all designs. Scaffold routing was imposed with CaDNAno v2.4.13.

SIMULATIONS

Short oxDNA protocol was used. Start conformations were generated by importing the caDNAno files into oxView using the integrated TacoxDNA converted.
The start conformation of the MagicDNA design was relaxed with a rigid body simulation, where each linear segment acted as a rigid body, using the oxView rigid body simulation tool before the start of the simulation protocol. This was done to alleviate the overstretching of covalent bonds present for this designs immediately after file conversion because of the placement of linear segments within the caDNAno files exported from MagicDNA.

Initial gradient descent was performed on CPU (13th Gen Intel Core i5-13400 × 16) on a Linux workstation (Linux 6.17.0-1032-oem, 64-bit, Ubuntu 24.04.4 LTS). OxDNA version v3.7.0 was compiled with GCC 11.2.0. and CMake 3.28.3. Random seed 0 was used for all initial minimizations, even though a deterministic steepest descent was used.

An ensemble of N=10 simulation repeats was performed for each structure. Random seeds 1-10 were used, respectively.

MD simulations were performed on GPUs (NVIDIA H200, H100, A100, V100) using oxDNA version v3.7.0 compiled with GCC 13.3.0, CMake 3.30.5 and CUDA 12.6.2.

The Aalto University high-performance computing cluster, Triton, was used to run the MD simulations in parallel.
